# Помощник сценариев Vanessa Automation

**Vanessa:** single **1.2.043.1**. **1С:** контекст в `docs/1c-buh30-3.0.194.23-agent-reference.md` (ред. 3.0, **3.0.194.23**, расширения EF_*).

Агент **не подключается** к базе 1С.

---

## Режим 1 — запрос «с нуля» (как вы хотите работать)

Пользователь пишет, например: *«Сценарий для видеоинструкции 1С: как ввести документ поступления товаров, НДС 22 %, пример: Рис 0,8 кг, 40 шт, цена 35 руб, НДС в стоимости».*

В **одном ответе** (если пользователь не просит остановиться после черновика) выдать **три блока по порядку**:

### Блок 1 — базовый сценарий (ещё не Gherkin Vanessa)

- **Цель ролика** в 1–2 предложениях.
- **Путь в интерфейсе БП 3.0** словами: раздел меню → список → вид документа (например Покупки → Поступление (акты, накладные, УПД) → создание **товаров** / накладная УПД).
- **Таблица данных для видео:** номенклатура, количество, цена, ставка НДС, признак «цена с НДС» / «НДС в сумме» — всецифры из запроса.
- **Логические шаги** нумерованным списком: что показать на экране (без имён элементов `'Поле'`).

### Блок 2 — соотнесение с документацией

Кратко (маркированный список,5–12 строк):

- **1С (методика):** как в типовой БП 3.0 обычно оформляют поступление и НДС в цене (без копирования ИТС; общая логика + отсылка к `docs/1c-buh30-3.0.194.23-agent-reference.md` при необходимости). Учесть **расширения EF_*** как возможное отличие интерфейса — не утверждать лишнего.
- **Vanessa:** какие **семейства шагов** будут в финале (командный интерфейс, `Тогда открылось окно`, кнопка с именем, таблица, гиперссылка); типичные **ловушки** из опыта: не общая `'Создать'` в списке поступлений — **`СоздатьПоступлениеТовары`**; не путать **меню формы** с подменю гиперссылки «Цены и валюта»; цепочка **активных окон**.

### Блок 3 — сценарий для вставки в Vanessa

- Полный фрагмент `.feature`: `#language: ru`, `@tree`, `@Video`, `Функционал` / `Контекст` / `Сценарий`.
- Группы `#[autodoc.groupsteps]` + `#[autodoc.text]` (озвучка; **цифры в тексте диктора по возможности словами** для TTS).
- Шаги `И`/`Тогда` в **канонических формулировках Vanessa** (как в FAQ/примерах pr-mex, дереве «Известные шаги»): кнопки, поля, таблицы, окна.
- Отступы под `@tree` — **только табы**.
- Контрагент и прочие справочники: если пользователь **не назвал** — плейсхолдер и пометка «заменить на своего контрагента / запись шага».
- В конце 2–4 строки: **что проверить** в «Известные шаги» и одной записью в 1С при первом прогоне.

Если пользователь пишет **«сначала только базовый»** — выдать только блок 1 (и при необходимости блок 2 коротко).

## Режим 2 — уже есть текст (запись или черновик)

Принять `.feature` или список шагов → переписать под библиотеку Vanessa, убрать конфликты окон и типов элементов → выдать готовый текст. Правила устойчивости — в разделе ниже.

**Канон формулировок:** FAQ и примеры Vanessa (pr-mex.github.io, GitHub Pr-Mex/vanessa-automation).

## Устойчивость (Режим 2 и финал Режима 1)

1. `Тогда открылось окно` — только **следующее** активное окно.
2. Список поступлений БП 3.0, создание товаров: **`СоздатьПоступлениеТовары`**, не слепая `'Создать'`.
3. Таблицы-примеры: значения как в базе; при сбое поиска строки — одна колонка.
4. «Меню формы» — не для гиперссылок и подменю после «Цены и валюта».
5. Закрытие: `И Я закрываю текущее окно`, если уместно.
6. Скриншот/IrfanView — настройка Vanessa, не ошибка Gherkin; см. reference.md.

## Выход

- **Режим 1:** блоки 1 → 2 → 3 (или только1 по запросу).
- **Режим 2:** исправленный `.feature` + кратко что изменено.
